# Датасеты для извлечения характеристик товаров

В этой папке собраны ссылки и краткие описания наборов данных, которые рассматривались для задачи извлечения характеристик товаров из текстовых карточек.

Задача проекта — получить из названия, описания и данных продавца пары:

```
характеристика → значение
```

Например:

```
бренд → Samsung
объём памяти → 256 GB
цвет → чёрный
```

Значение должно подтверждаться исходным текстом карточки. Изображения в текущей версии задачи не рассматриваются как вход модели.

## Файлы

- [`datasets.json`](./datasets.json) — машинно-читаемый список источников, ссылок, полей, размеров, преимуществ и ограничений.
- `README.md` — краткое описание наборов обычным языком.

## Простое объяснение терминов

- **evidence** — подтверждающий фрагмент текста: место в карточке, которое доказывает найденное значение.
- **span** — границы подтверждающего фрагмента: позиции, с которых он начинается и на которых заканчивается в исходной строке.

Например, для текста `Смартфон Samsung с памятью 256 GB` ответ `память → 256 GB` должен содержать подтверждающий фрагмент `256 GB`. Если сохранены его позиции в строке, это и есть границы фрагмента.

## Краткое сравнение

### WDC PAVE

Англоязычный набор примерно из 1 420 карточек. В нём есть и заголовок, и описание товара, а также размеченные характеристики и нормализованные значения.

Преимущества:

- наиболее близкая структура «название + описание → характеристики»;
- есть ручная проверка и нормализация;
- опубликованы готовые JSONL-файлы.

Недостатки:

- всего пять категорий товаров;
- около 70 атрибутов, причём нормализованная версия покрывает только часть из них;
- точные границы подтверждающего фрагмента в опубликованном формате отсутствуют;
- лицензионные условия нужно уточнить отдельно.

Источники: [официальная страница](https://webdatacommons.org/structureddata/wdc-pave/) и [репозиторий](https://github.com/wbsg-uni-mannheim/wdc-pave).

### MAVE

Крупный англоязычный набор Amazon — около 2,23 млн положительных товаров. В разметке есть характеристики, значения и указатели на текстовые фрагменты.

Преимущества:

- большой объём;
- есть положительные и отрицательные товары;
- схема предусматривает \`pid\`, \`begin\` и \`end\` для подтверждающего фрагмента.

Недостатки:

- в репозитории разметка отделена от исходных текстов;
- тексты нужно восстанавливать через Amazon Review Data 2018;
- часть разметки получена моделями и правилами, поэтому возможны ошибки;
- полноценная загрузка и восстановление корпуса требуют отдельной работы;
- доступ к датасету пока дополнительно выясняется.

Источник: [репозиторий MAVE](https://github.com/google-research-datasets/MAVE).

### AE-110K и AE-pub

Англоязычные данные AliExpress, ориентированные на извлечение характеристик из названий товаров. Значение либо буквально встречается в заголовке, либо используется \`NULL\`.

Преимущества:

- проверяет, что модель не должна выдавать значение, которого нет в title;
- есть отрицательные случаи и \`NULL\`;
- существует очищенная версия с более воспроизводимым разделением данных.

Недостатки:

- только заголовки, без описаний товаров;
- это не полноценный ручной эталон;
- часть отрицательных примеров сформирована автоматически;
- плохо проверяет работу с длинным свободным описанием.

Источники: [AE-110K](https://github.com/cubenlp/ACL19_Scaling_Up_Open_Tagging) и [очищенная версия AE-pub](https://www.tkl.iis.u-tokyo.ac.jp/~ynaga/acl2022/).

### OA-Mine

Англоязычный набор для извлечения новых, заранее неизвестных характеристик из названий товаров. В аннотациях есть значения и символьные границы найденных фрагментов.

Преимущества:

- проверяет сценарий с неизвестными заранее атрибутами;
- есть точные границы найденных значений;
- охватывает много категорий;
- архив \`amazon.zip\` уже находится в текущем проекте.

Недостатки:

- ручная и слабая разметка представлены не одинаково;
- основной сценарий — title-only;
- состав локального архива нужно сверять с каталогом \`annotations\`;
- описание товара не является стабильным обязательным полем.

Источник: [репозиторий OA-Mine](https://github.com/xinyangz/OAMine).

### ExtractGPT subsets

Небольшие подготовленные поднаборы OA-Mine и AE-110K: примерно 1 943 и 2 092 карточки соответственно.

Преимущества:

- проще и быстрее использовать для первых экспериментов;
- данные приведены к удобному формату JSONL;
- позволяют сравнивать два источника в едином процессе.

Недостатки:

- это производная упаковка уже существующих наборов, а не новый независимый эталон;
- часть исходных идентификаторов и границ может быть потеряна;
- копию нельзя использовать как независимый тест, если оригинал попал в обучение.

Источник: [репозиторий ExtractGPT](https://github.com/wbsg-uni-mannheim/ExtractGPT).

### GreenMap/ru-product-characteristics-extraction

Русскоязычный набор примерно из 4 670 строк в формате \`prompt/response\`.

Преимущества:

- русский язык;
- простой формат для чтения и проверки;
- может показать, как организовать ответ с названием характеристики и значениями.

Недостатки:

- в каждом примере обычно размечен только один атрибут, хотя в исходном тексте их может быть больше;
- нет полноценного отрицательного класса;
- нет стабильных product ID и категорий;
- нет готовой разметки подтверждающих фрагментов и их границ;
- для оценки полноты потребуется дополнительная ручная разметка.

Источник: [карточка на Hugging Face](https://huggingface.co/datasets/GreenMap/ru-product-characteristics-extraction).

### ke-products

Большой преимущественно русскоязычный каталог KazanExpress — около 2,06 млн карточек. В нём есть заголовки, описания, категории, продавцы и сырые характеристики.

Преимущества:

- большое количество русских реальных карточек;
- есть title, description, иерархия категорий и идентификаторы;
- характеристики часто представлены в формате \`ключ: значение\`;
- можно анализировать разные категории и продавцов.

Недостатки:

- seller attributes не являются проверенной разметкой;
- встречаются свободные списки характеристик без ключей;
- возможны HTML, ссылки, пропуски, шум и дубликаты;
- нет готовых подтверждающих фрагментов и их границ, а также ручного контрольного набора;
- полноту характеристик относительно текста нужно проверять самостоятельно.

Источник: [карточка на Hugging Face](https://huggingface.co/datasets/nyuuzyou/ke-products).

### wb-products

Большой сырой каталог Wildberries с русскоязычными карточками. Опубликовано 12 архивов общим размером около 15,8 ГБ; полный объём не подтверждён.

Преимущества:

- дополнительный русский marketplace-домен;
- есть названия и описания товаров;
- можно исследовать переносимость подходов между площадками.

Недостатки:

- большой объём загрузки;
- нет единого словаря характеристик;
- нет готовой ручной разметки extraction;
- состав и статистика полной версии требуют проверки.

Источник: [карточка на Hugging Face](https://huggingface.co/datasets/nyuuzyou/wb-products).

### products-description

Небольшой русскоязычный набор на 400 строк: около 360 строк для обучения и 40 для проверки. Входом служит описание товара, ответом — структурированный JSON.

Преимущества:

- есть русские тексты и структурированные ответы;
- удобен для проверки формата вывода и парсинга.

Недостатки:

- слишком маленький объём;
- ответы покрывают только часть характеристик описания;
- встречаются \`NaN\` и неполные ответы;
- происхождение и ручная проверка описаны недостаточно.

Источник: [карточка на Hugging Face](https://huggingface.co/datasets/salehardec/products-description?duplicate=true).

### Home Depot Product Search Relevance

Англоязычный набор карточек товаров Home Depot. В локально скачанной части есть три связанные таблицы: поисковые пары товаров, структурированные характеристики и описания товаров.

По проверенной локальной копии:

- `train.csv` — 74 067 строк и 54 667 уникальных товаров;
- `attributes.csv` — 2 044 803 строки, 5 411 разных названий характеристик;
- `product_descriptions.csv` — 124 428 описаний;
- у всех товаров из `train.csv` есть описание;
- медианная длина описания — 716 символов, средняя — около 840;
- примерно половина значений из `attributes.csv` буквально встречается в описании.

Преимущества:

- есть одновременно название, подробное описание и пары `attribute — value`;
- большой объём данных;
- характеристики включают бренд, материал, цвет, размеры, вес и технические параметры;
- описания часто содержат bullet-пункты с характеристиками, поэтому по ним можно предварительно восстановить `evidence` и `span`;
- все три файла связываются через `product_uid`.

Недостатки:

- отдельной разметки `evidence` и границ `span` нет;
- `train.csv` размечен по релевантности поискового запроса, а не по качеству извлечения характеристики;
- отсутствие характеристики не означает отрицательный пример;
- большая часть товаров относится к ремонту, дому и строительству, а не к электронике;
- простое совпадение значения с описанием может давать ложные совпадения, особенно для коротких числовых значений;
- условия доступа Kaggle требуют принятия правил соревнования.

Роль в проекте: большой англоязычный источник для weak labeling, проверки поиска значений в описаниях и тестирования нормализации. Полноценным gold benchmark для extraction он не является.

Источник: [Home Depot Product Search Relevance на Kaggle](https://www.kaggle.com/competitions/home-depot-product-search-relevance/data).

### SynthAVE

Синтетический многоязычный набор для проверки пары «характеристика–значение». В текущей версии есть английский, немецкий, французский, испанский и итальянский языки.

Преимущества:

- есть состояния «подтверждено», «неверно» и «неизвестно»;
- подходит для отдельной проверки verification;
- поддерживает несколько языков.

Недостатки:

- это не полноценный реальный каталог товаров;
- русского и китайского языков нет;
- английская часть не полностью проверена экспертами;
- лицензия требует отдельного изучения.

Источник: [репозиторий SynthAVE](https://github.com/amazon-science/SynthAVE).

### JAVE / M-JAVE / MEPAVE

Китайский набор, преимущественно по одежде, с разметкой извлечения из текстовых фрагментов.

Преимущества:

- китайский язык;
- есть атрибуты, значения и размеченные текстовые фрагменты;
- присутствует небольшая демонстрационная выборка.

Недостатки:

- полный набор предоставляется по заявке;
- открытой демонстрационной выборки недостаточно для полноценной оценки;
- домен в основном ограничен одеждой;
- условия использования полного корпуса требуют уточнения.

Источник: [репозиторий JAVE](https://github.com/jd-aig/JAVE).

### MEP-3M

Большой китайскоязычный набор примерно из 3 млн товаров с названиями и категориями.

Преимущества:

- большой объём китайских названий;
- есть категории для отбора нужных товарных доменов;
- можно использовать карточки для собственной разметки.

Недостатки:

- готовой разметки характеристик нет;
- для extraction потребуется собственная аннотация;
- изображения не нужны для текущей текстовой задачи;
- условия использования нужно проверить.

Источники: [репозиторий](https://github.com/ChenDelong1999/MEP-3M) и [карточка на Hugging Face](https://huggingface.co/datasets/chendelong/MEP-3M).

### CIC / Alibaba Customer Interaction Dataset

Китайский набор примерно из 1,9 млн записей взаимодействия покупателей с товарами одежды. В схеме есть названия товаров и атрибуты.

Преимущества:

- китайский товарный домен;
- есть названия и атрибуты;
- большой объём записей.

Недостатки:

- строка описывает взаимодействие, а не обязательно уникальный товар;
- реальные файлы находятся во внешних источниках;
- не подтверждено, что атрибуты буквально присутствуют в title;
- query и идентификаторы могут создавать утечку данных.

Источник: [репозиторий CIC](https://github.com/ixuejiaozhao/Alibaba-Custermers-Interaction-Dataset).

### JDivPS

Набор, связанный с поиском товаров JD. В нём есть категории, бренды, размеры и другие признаки, но названия и значения в значительной степени обезличены или закодированы.

Преимущества:

- может быть полезен для экспериментов с поиском и категориальными признаками;
- содержит несколько типов товарных полей.

Недостатки:

- нет надёжно читаемого исходного текста;
- нельзя проверить, присутствует ли значение в карточке;
- не является датасетом текстового извлечения характеристик.

Источник: [репозиторий JDivPS](https://github.com/DengZhirui/JDivPS).

### MAE

Большой мультимодальный англоязычный набор Amazon: примерно 2,2 млн товаров, 4 млн изображений и 7,6 млн пар attribute-value.

Преимущества:

- очень большой масштаб;
- есть тексты, изображения, атрибуты и значения;
- полезен для анализа товарного домена и слабого обучения.

Недостатки:

- загрузка большого объёма может занимать много времени;
- изображения избыточны для текущей text-only задачи;
- значение из каталога может отсутствовать в разрешённом текстовом входе;
- автоматически собранные пары нельзя считать готовым эталоном.

Источник: [официальная страница MAE](https://rloganiv.github.io/mae/).

### CU-WS

Русскоязычный каталог товаров с описаниями, техническими параметрами и поисковыми взаимодействиями. В архиве три файла:

- `query_clicks.parquet` — 30 991 350 строк с `sku_id`, названием, брендом, ценой, поисковым запросом и позицией товара;
- `sku_desc.parquet` — 1 177 200 пар `sku_id`, `title`, `description`;
- `skus.pkl` — 546 069 товарных предложений, 6 963 категории и вложенные параметры продавца в формате name/value.

Преимущества:

- большой объём русскоязычных карточек;
- одновременно доступны заголовки, описания, категории и структурированные параметры;
- описания часто содержат разделы «Характеристики» и технические списки;
- можно связывать описание и параметры по идентификатору товара.

Недостатки:

- готовой ручной разметки извлечения, `evidence` и `span` нет;
- поисковые события не являются разметкой характеристик;
- набор широкий, а не электронный, поэтому нужные категории придётся отбирать;
- происхождение, лицензия и правила распространения архива требуют отдельного подтверждения;
- `skus.pkl` — исполняемо-опасный формат при неосторожной загрузке, использовать только ограниченный загрузчик.

В репозиторий добавлен исходный `cu_ws.zip` через Git LFS. Распакованная версия оставлена локально для анализа и не дублируется в Git.

Роль в проекте: крупный русскоязычный источник для слабой разметки и последующей ручной проверки. Эталонным набором для оценки extraction он не является.

Источник: локальный архив `cu_ws.zip`; публичная страница происхождения в архиве не указана.

## О данных и достоверности

Размеры в этом README — значения из карточек датасетов, документации авторов или исследовательского отчёта. Они не означают, что каждый архив был полностью скачан и проверен.

Важно различать:

- характеристики продавца и проверенную разметку;
- наличие значения в каталоге и наличие значения в исходном тексте;
- подтверждающий фрагмент текста и просто поле с готовым ответом — это не одно и то же;
- полный датасет и небольшую демонстрационную выборку;
- ручные labels и labels, созданные правилами или моделями.

Описания фиксируют состав и ограничения источников. Рекомендации по выбору датасетов и построению pipeline в этот README намеренно не включены.
